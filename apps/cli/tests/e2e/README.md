# Сквозные локальные сценарии CLI

Пять маршрутов `*.e2e.test.ts` проверяют локальную работу через собранный `relay`:

- документ сохраняет точный Markdown между процессами и отвергает устаревшую ревизию;
- workspace выбирает независимые проекты и сохраняет базу после удаления регистрации;
- задача с критерием проходит через завершённый план до опубликованного релиза;
- история сохраняет исходное намерение и явный результат участия;
- batch проверяет и применяет связанные изменения, читает полный/краткий рабочий набор
  и восстанавливает первоначальную квитанцию после следующих запусков.

Каждый тест создаёт собственные HOME, RELAY_HOME и проекты под корневой `.artifacts`.
Каждый шаг запускает новый бинарник с абсолютным путём и пустым PATH: Server, Git и
`relay-git-sync` не нужны. `finally` дожидается завершения команд и удаляет fixture.

Из корня репозитория с автоматической подготовкой бинарника:

```bash
bun x --no-install turbo run test:e2e --filter=@relay/cli
```

Если бинарник уже собран, достаточно `bun run --filter @relay/cli test:e2e`.
Адресный запуск из корня: `bun test --no-orphans --cwd apps/cli ./tests/e2e/local-workflow.e2e.test.ts`.
Runner использует `--no-orphans` как дополнительную очистку после аварии.

[Межприложенческий набор](../../../../tests/e2e/README.md) отдельно проверяет Git/Server-маршруты
и переиспользует CLI subprocess-harness из `helpers` без копирования.
Общие правила: [организация тестов](../../../../tests/README.md).
