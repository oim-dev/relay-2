# Архитектура Web

Визуальная основа приложения — исходное дерево Relay Web первой версии: экранные
композиции, CSS Modules, тема Mantine, навигация, Markdown, канбан и React Flow/ELK.
Данные адаптируются к текущим Contracts/Core. Общие границы компонентов определяет
[архитектура Relay](../../../docs/ARCHITECTURE.md).

## Владельцы

- `app` связывает провайдеры и маршруты.
- `compositions/layouts` организует шапку, сайдбар, крошки и рабочую область.
- `compositions/screens` сохраняет самостоятельные продуктовые страницы, библиотеку,
  канбан с окном задачи, планы, релизы и визуализации.
- `compositions/widgets` содержит самостоятельные составные области экранов.
- `domains` адаптирует текущие DTO к моделям представления и выполняет предметные
  действия через общий SDK. Модели представления не являются старым серверным API.
- `domains/relay-data` владеет общей записью, frozen requests и восстановлением receipt.
- `infra/tasks-api` создаёт единственный `createRelayClient`; `infra/workspace-events`
  обслуживает общую подписку проекта; `infra/browser-storage` обслуживает черновики.
- `ui` содержит исходные тему, редактор, renderer, визуальные состояния и механизмы DnD.

Алиасы `app/*`, `compositions/*`, `domains/*`, `infra/*`, `ui/*`, `shared/*` ведут
в соответствующие каталоги `src`. Публичные фасеты — `index.ts` и динамический
`lazy.ts`; внутренние импорты относительные. Профиль React SPA и Unit Architecture
находятся в [источниках разработки](DEVELOPMENT.md#источники-инструкций).

## Запись и черновики

```text
Исходный экран → доменный адаптер → @relay/rest-sdk → Server /api/v2 → Core
                      ↑                 │
                      └──── SSE ────────┘
```

Постоянный `projectId` закреплён за поддеревом запросов и форм. Кеш и черновики
не переносятся в другой проект. Серверные карточки находятся в SWR, несохранённый
ввод — отдельно. SSE и reconnect перечитывают данные, сохраняя исходную версию формы.

Команды содержат исходные guards и автора Server. При неопределённом исходе сохраняется
первоначальный запрос; повтор проверяет его квитанцию. Составные действия используют
атомарный batch. Разделы принадлежат проекту, участие — приложению, этапы и membership —
плану. Комментарии дописываются отдельно от ревизии содержания задачи.

Готовность задач, планов и релизов читается из проекций Core. Статус реализации задаётся
явно, активное участие является отдельным свойством. Web не возвращает прежние формулы
готовности продукта. Неподдержанные счётчики остаются неизвестными, а не нулевыми.

Обзор читает компактный агрегат и ограниченные подборки текущего API. Он сопоставляет
поколения страниц и проверяет поколение после составного чтения. Крупные списки
продолжаются только по действию; прежние метрики оператора не объявляются доступными.
Геометрия графиков принадлежит Web; их факты берутся из текущих структурированных данных.

Подборки задач используют `taskViews` без тел и журналов. Названия досок и первых
блокеров загружаются одним адресным `getMany summary`. Заведомо пустые виды не читаются
повторно, если их ноль подтверждён исходным агрегатом. Ограничение числа карточек
ответа не означает ограниченного SQL-чтения: фильтры знаний и прогресс каждого плана
или релиза могут обходить полный набор/граф в Core. Общий overview также сохраняет
стоимость своего текущего Core reader.

## Навигация и поставка

Доска остаётся фоном модальной карточки задачи. Граф истории сохраняет камеру при
чтении материала. Канонические ссылки используют постоянную идентичность проекта;
совместимые адреса Relay 2 разрешает отдельная `entity-route` boundary.

Имена регистраций и известные slug служат совместимыми алиасами только при одном
владельце; неоднозначный alias не выбирает первый проект. Канонизация ведёт к ID.
Реестр Server фиксируется при запуске, а отображаемое имя проекта читается из его
актуальной карточки. Переименование карточки не считается обновлением реестра.

Ручной Git Sync хранит исходный requestId отдельно от cached доставки. Периодическое
наблюдение очереди/исполнения читает только outcome. Если весь ответ потерян до
получения ID, интерфейс не может восстановить квитанцию: неизвестный исход не
разрешает молча запустить ещё один now.

Server разрешает HTML fallback для известных веток и включает assets/Workers Vite
в бинарник. Изменение дерева URL требует согласования с
`apps/server/src/modules/assets/spa-routes.ts`.
