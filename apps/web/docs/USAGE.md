# Работа в Web

Web помогает связать описание продукта с документами, задачами, планами и результатами
работы. Данные общие с локальной CLI: после изменения через другой интерфейс открытые
карточки обновляются по событиям сервера.

## Открыть проект

Откройте URL Relay Server с подключённой сборкой Web. В workspace выберите проект;
в локальном режиме доступный проект открывается сразу. Недоступная регистрация
показывается с причиной отказа. Добавление проектов и управление сервером выполняются
вне Web — через [CLI](../../../docs/CLI.md) и [Server](../../server/README.md).

Несколько workspace-имён могут ссылаться на один физический проект. Начальный список
сохраняет эти регистрации, а селектор в шапке объединяет их по постоянному ID и
показывает все имена алиасов. Недоступные регистрации остаются отдельными вариантами.

На широком экране разделы находятся слева, на узком — в выдвижном меню. Проект можно
сменить в шапке. Переключатель темы меняет светлую и тёмную схемы; первоначально
используется системная настройка.

«Обзор» показывает актуальные числа записей и распределение задач по колонкам.
Предпросмотры материалов ведут к карточкам и полным каталогам. Число задач в «Готово»
не заменяет проверку их критериев и обязательств.

## От описания продукта к работе

1. Заполните «Паспорт продукта»: название, краткое и подробное описание.
2. Добавьте фичу в «Возможностях» и при необходимости её сценарии.
3. Создайте приложение, затем реализацию фичи или сценария в этом приложении.
   Статус реализации сохраняется явно; активность участия в приложении — отдельное
   свойство. Готовность не вычисляется браузером из числа задач.
4. Сохраните поясняющий документ в «Библиотеке знаний». Выберите вид, состояние,
   раздел и закрепление; добавьте отношения к нужным сущностям.
5. На доске создайте задачу, опишите работу в Markdown и свяжите её с предметными целями.

Разделы библиотеки общие для проекта. Их создание, переименование, перемещение и
снятие требуют версии проекта, независимо от открытого документа. Снятие отношения
или раздела не является удалением самой сущности.

## Задачи и обсуждения

Выберите доску, при необходимости найдите задачи по тексту или включите фильтр блокеров.
Каждая колонка имеет собственное продолжение списка. В карточке доступны:

- изменение названия и Markdown-описания;
- отдельное перемещение между досками и текущими колонками;
- добавление, изменение, выполнение, повторное открытие и снятие критерия;
- комментарии с заголовком и содержанием — существующие комментарии не редактируются;
- родитель и дети, зависимости, необязательные связи и предметные цели;
- серверный прогресс и причины, мешающие завершению.

Непройденный критерий или другое обязательство может запретить перевод в «Готово».
При отказе исправьте указанную причину; интерфейс не обходит проверку Core.

## План, этапы и релиз

В «Планах» опишите цель, границы и ожидаемый результат, выберите область и участников.
Добавьте этапы и включите задачи в их состав. Задачу можно снять или перенести в этап
другого плана с проверкой версий обеих сторон. Прогресс этапов и плана приходит с сервера.

Перевод плана в новое состояние — отдельное действие. Создайте релиз: задайте версию,
описание, плановую дату и состав планов. Допустимость публикации проверяет Core по
текущему состоянию работы. Публикация релиза
сохраняет предметное состояние Relay; сборка, выкладка программ и выпуск пакетов
выполняются внешними инструментами.

## История и продолжение работы

Начните рабочую сессию и откройте намерение. По мере работы добавляйте прогресс,
результат или отмену намерения, сохраняя ссылки, проверки и следующий шаг.
Материалы истории неизменяемы: продолжение добавляется новой записью.

Карточка сессии показывает контекст продолжения, открытые намерения, материалы,
участия исполнителей и дерево поручений. Доступны действия принятия ответственности,
приостановки, продолжения, завершения, отмены и создания дочерней работы. Их допустимость
проверяет Core. Автор записей берётся из контекста запущенного сервера.

## Черновики и конкурентное изменение

Закрытие редактора с сохранением черновика позволяет вернуться к вводу в этой же
вкладке, в том числе после перехода в другой проект. Обновление карточки по SSE
не заменяет несохранённый текст. Перезагрузка страницы или закрытие вкладки завершает
жизнь этих черновиков: это не долговременное хранилище.

Если карточка изменилась после открытия формы, сохранение может вернуть конфликт.
Черновик остаётся доступным вместе с исходной версией. Сравните его с актуальной
карточкой; если начинаете редактирование заново, сначала сохраните нужный текст,
затем явно отбросьте старый черновик. Автоматического слияния или обновления исходной версии нет.

При потере ответа неизвестно, сохранилась ли запись. Поля временно блокируются,
а повтор проверяет исходную операцию по её ключу и квитанции. Используйте предложенное
действие проверки; новый ввод не заменяет незавершённый запрос.

Если при продолжении списка сервер сообщает `PAGE_CHANGED`, обновите список с начала.
Карточки разных поколений не объединяются в одно окно.

## Что означает Git Sync

Индикатор присутствует над рабочей областью. Раскройте его для просмотра подключения,
worker, режима, фазы, ожидающих изменений, конфликтов, последнего успешного обмена,
ошибок и актуальности сведений. «Неизвестно» не означает пустую очередь или отсутствие
конфликтов. Подключённые события сервера также не подтверждают доставку в Git.

«Обновить статус» читает состояние, «Синхронизировать сейчас» запускает одно ручное окно
обмена через Server/Runtime. Принятый запрос можно наблюдать по requestId без нового
запуска. Конфликты и ожидание зависимостей отображаются отдельно. Подключение Git,
управление службами и разрешение конфликтов описаны в
[руководстве Git Sync](../../../docs/CLI.md#git-синхронизация).

## Адреса и навигация

Базовый адрес проекта — `/projects/:projectId`, где `projectId` — постоянный ID из
реестра сервера. Читаемый slug не заменяет ID в этом маршруте.

| Путь после адреса проекта            | Содержимое                                                        |
| ------------------------------------ | ----------------------------------------------------------------- |
| пустой путь                          | Обзор                                                             |
| `/knowledge/:kind`                   | `product`, `feature`, `scenario`, `application`, `implementation` |
| `/entities/:ref`                     | Адресная карточка; вид определяет экран или перенаправление       |
| `/documents`                         | Библиотека знаний                                                 |
| `/board`                             | Выбор доски и задачи                                              |
| `/tasks/:ref`                        | Карточка задачи                                                   |
| `/plans`, `/plans/:ref`              | Каталог и карточка плана                                          |
| `/releases`, `/releases/:ref`        | Каталог и карточка релиза                                         |
| `/history`, `/history/sessions/:ref` | История и рабочая сессия                                          |

Создаваемые интерфейсом ссылки используют постоянные ID и переживают перенумерацию
читаемых ключей. Фильтры каталогов сохраняются в query-параметрах; переходы Back/Forward
восстанавливают адрес. Прямую ссылку на материал истории интерфейс открывает в контексте
его сессии. Для обычной навигации используйте ссылки и фильтры самого Web.
