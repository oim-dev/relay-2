# Измерения производительности

Место для будущего воспроизводимого стенда. Исполняемых сценариев и команды запуска
пока нет; они добавляются вместе с предметной реализацией по отдельному запросу.

## Запуск

Измерения производительности и нагрузочные сценарии выполняются **только вручную
по явному запросу**. Они не входят в CI, `check`, `test:all`, обычные тестовые scripts
и их зависимости в Turbo.

Сценарии CLI будут размещаться в `benchmarks/cli/` с именами `*.bench.ts`, отдельно
от обнаруживаемых Bun test файлов. Для управления нагрузкой будет использоваться отдельный
Bun-сценарий с `Bun.spawn()`, запускающий настоящий бинарник с заданным числом клиентов.
Команда ручного запуска определяется при появлении стенда.

## Сценарии и показатели

Планируем измерять:

- запуск собранного CLI;
- чтение, запись и атомарные пакеты на разных объёмах данных;
- работу с отдельными SQLite-базами 10+ проектов на одном ПК;
- несколько писателей одной проектной БД и длительную смешанную нагрузку;
- параллельные CLI/Server/Git Sync, ожидание записи и рост WAL;
- обмен 10+ независимых экземпляров через общий origin;
- восстановление из локального Git и origin;
- задержки p50/p95/p99, пропускную способность, ошибки и конфликты, потребление памяти.

Сценарии Server и Git Sync добавляются по мере реализации компонентов.
Сохранность данных и предметные инварианты проверяются после нагрузки: успешное
завершение процессов само по себе не доказывает корректность итогового состояния.

Небольшая проверка корректности двух конкурирующих записей относится к обычным
[функциональным тестам](../tests/README.md). Массовая конкуренция и измерение задержек
относятся к этому стенду.

## Воспроизводимость и материалы

Для каждого запуска фиксируются:

- версии приложения, Bun и схема данных;
- платформа, ресурсы машины и настройки надёжности БД;
- способ подготовки и объём данных, seed при генерации;
- число клиентов, операции, длительность и условия остановки;
- наличие прогрева и способ измерения времени;
- результаты успешных операций, ошибок и конфликтов раздельно.

Базы, origin и процессы стенда изолируются от пользовательских данных. Ресурсы
освобождаются при завершении и отмене. Результаты, логи и подготовленные данные
сохраняются в `.artifacts/YYYY-MM-DD/<название-измерения>` и не коммитятся.

Численные бюджеты определяются после первых измерений на зафиксированном окружении.
