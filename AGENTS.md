# Работа над Relay

- Общение, документация и авторские комментарии — на русском языке.

## Контекст и область работы

- Relay — новая реализация на Bun + TypeScript в Turborepo. Сейчас переносим основной
  функционал в локальную CLI и необходимые библиотеки. Готовность определяется
  реализацией и проверками, а не наличием каталога или пакета.
- Server, Web, MCP, Git-синхронизация, HTTP-клиент, IPC, установщик и миграция старых
  данных отложены. Локальные команды работают без сервера, браузера, MCP и Git origin.
- Перед предметной работой читай [архитектуру](docs/ARCHITECTURE.md), README и AGENTS.md
  затрагиваемых компонентов. Локальные инструкции дополняют общие; предложения целевой
  архитектуры не считаются реализованными возможностями.
- Первая версия находится в `../relay`: используй её сценарии, правила и известные
  проблемы, сохраняя нужные инварианты. Копировать старую архитектуру не требуется;
  инструкции и результаты проверок старого checkout относятся только к нему.
- Соблюдай границы владельцев из архитектуры. Приложения не импортируют исходники
  друг друга; местные ограничения и инварианты находятся в AGENTS.md компонентов.

## Playground и работа с человеком

- Основная среда пользователя для знакомства с результатом и ручного тестирования —
  `/home/gromov/projects/relay/playground` (`../playground` относительно этого checkout).
  Внутри находятся самостоятельные проекты `projects/commerce` и `projects/observability`.
  Запускай Relay из корня playground для workspace или из корня выбранного проекта.
  Развёртывание и использование описаны в [README playground](https://github.com/oim-dev/relay-playground).
- Агент выбирает удобные checkout, инструменты и способы разработки в рамках правил
  проекта. Совместные с человеком ручные проверки проводи в playground; собственные
  автоматические проверки выполняй на изолированных fixtures по [правилам наборов](tests/README.md).
- Перед передачей изменений CLI на ручную проверку обнови доступный пользователю
  бинарник: `~/.local/bin/relay` ссылается на
  `/home/gromov/projects/relay/relay-2/apps/cli/dist/relay`. При работе в другом checkout
  убедись, что команда `relay` в playground запускает сборку с нужными изменениями.

## Обязательные правила разработки

- Для TypeScript читай и применяй [стайлгайд](docs/development/TYPESCRIPT-STYLEGUIDE.md):
  документация, точные контракты, декомпозиция и стоимость сценария входят в реализацию.
- Для изменений поведения и тестов применяй [правила тестирования](docs/development/TESTING.md)
  и [организацию наборов](tests/README.md). Зелёные тесты необходимы, но не заменяют ревью.
- Для README и других документов применяй [правила документации](docs/development/DOCUMENTATION.md).
  README — паспорт для читателя; у подробного правила должен быть один основной источник.
- До нетривиального изменения прочитай соседний код и публичные контракты, определи
  владельца сценария, границы, инварианты и проверки. Переиспользуй подходящие решения.
- Сохраняй обозримую область изменения: рефакторинг затрагивает необходимую ответственность
  и не смешивается с несвязанными возможностями. Не перезаписывай чужую работу.
- Перед завершением перечитай итоговый diff: устрани дубли правил, лишние уровни
  косвенности, скрытые побочные эффекты и непонятные контракты.

## Ревью в OpenCode

- Основной агент назначает и координирует ревью. После изменения предметных правил,
  контрактов, транзакций, составных запросов или существенной декомпозиции он запускает
  `relay-reviewer` перед итоговым ответом.
- При изменении существенного поведения, тестов, fixtures или организации наборов
  привлекай `relay-test-reviewer`. [Карта сценариев](docs/development/TEST-COVERAGE.md)
  помогает найти проверки, но не заменяет чтение утверждений.
- Определения ревьюверов находятся в `.opencode/agents/`. Передавай цель, область diff,
  базовую ревизию, инварианты, чужие незакоммиченные изменения, выполненные проверки
  и пути к логам. Разделяй ревью реализации и достаточности тестов.
- Ревьюверы могут выполнять проверки и исправления; результаты возвращают родителю
  без цепочки взаимных ревью. Подтверждай замечания по коду и сценарию, устраняй дефекты,
  обосновывай несогласие и сообщай оставшиеся существенные проблемы пользователю.
- Повторное ревью и повтор пройденных проверок нужны после существенных исправлений
  или при конкретном сомнении. Используй переданные результаты на том же состоянии кода,
  не поручай каждому агенту полный прогон.
- Нагрузку запускай только по явному запросу, вне CI и штатных проверок, по
  [методике CLI](docs/development/CLI-PERFORMANCE.md).

## Отчёты и рабочие артефакты

- Все отчёты, журналы выполнения, результаты проверок, логи, скриншоты,
  дампы, черновики и одноразовые экспериментальные материалы сохраняй
  только в `.artifacts/YYYY-MM-DD/<понятное имя>`.
  Используй фактическую текущую дату; внутри допустимы файлы и каталоги.
- `.artifacts/` исключён из Git. Запрещено коммитить эти материалы,
  принудительно добавлять их через `git add -f` или переносить отчёты
  и их фрагменты в отслеживаемые файлы репозитория.
- Итог поручения сообщай в ответе пользователю. При необходимости
  прикладывай ссылки на материалы в `.artifacts/`.

## Изменение агентских инструкций

- Создавать, изменять, удалять или переименовывать AGENTS.md и другие
  файлы инструкций агентов разрешено только по явному запросу пользователя,
  непосредственно предусматривающему такое действие.
- Запрет распространяется на корневые и вложенные файлы, включая изменения
  через генераторы и скрипты.
- Поручение изменить код, документацию или настройки проекта не является
  разрешением менять агентские инструкции.
- По собственной инициативе не добавляй туда правила, уточнения,
  исправления, выводы или сведения о выполненной работе.
