# Relay

Каркас новой версии Relay — рабочей памяти проекта для людей и AI-агентов.
Монорепозиторий на **Bun + Turborepo + TypeScript**.

Цель, обсуждение архитектуры и источники знаний: [PROJECT.md](PROJECT.md).
Примерная архитектура: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).
Текущий этап — перенос основного функционала в CLI; Server, Web и MCP отложены
до появления рабочей CLI с перенесённым основным функционалом.

## Подготовка

Нужен Bun **1.4.3**, закреплённый в `.bun-version` и `packageManager`.
Установка нужной версии: [инструкция Bun](https://bun.com/docs/installation).

```bash
bun --version
bun install --frozen-lockfile
bun run check
```

Зависимости и инструменты разработки запускаются через Bun. Версии зависимостей
закреплены в манифестах и общем `bun.lock`.

## Структура

```text
apps/
  cli/                  → бинарник relay
  sync/                 → бинарник relay-sync
packages/
  contracts/            → переносимые схемы и типы
  core/                 → предметные операции и правила
  storage/              → локальная БД и транзакции
  project-runtime/      → локальный контекст и подключения проектов
  rest-sdk/             → общий HTTP-клиент
  typescript-config/    → профили TypeScript
tests/
  e2e/                  → будущие сквозные сценарии
benchmarks/              → будущие измерения производительности
```

Все приложения и библиотеки сейчас являются заглушками. Бинарники печатают
сообщение о каркасе и завершаются. База данных, синхронизация, IPC и предметные
команды пока не реализованы.

## Разработка и сборка

| Команда                            | Назначение                                                               |
| ---------------------------------- | ------------------------------------------------------------------------ |
| `bun run dev`                      | Наблюдение за сборкой CLI и Sync                                         |
| `bun run dev:cli` / `dev:sync`     | Пересборка выбранного бинарника при изменениях                           |
| `bun run build`                    | Типизация и сборка всех приложений                                       |
| `bun run build:cli` / `build:sync` | Сборка выбранного приложения                                             |
| `bun run start:cli` / `start:sync` | Запуск ранее собранной заглушки                                          |
| `bun run lint`                     | Oxlint                                                                   |
| `bun run typecheck`                | Проверка типов всех приложений и библиотек                               |
| `bun run format:check` / `format`  | Проверка / применение Prettier                                           |
| `bun run check`                    | Форматирование, lint, типы, сборка и все предусмотренные тестовые наборы |

`dev` для бинарников сейчас только пересобирает файлы. Выполнение — отдельной командой
`start:*` или прямым запуском результата сборки. Постоянные сервисы появятся при реализации.

Артефакты текущей платформы:

```text
apps/cli/dist/relay
apps/sync/dist/relay-sync
```

На Windows исполняемые файлы могут иметь расширение `.exe`. Кроссплатформенный комплект,
установщик и обновление приложения относятся к следующим этапам.

Библиотеки экспортируют TypeScript-исходники и включаются в сборку потребителя.
Отдельная сборка библиотечных `dist` не нужна. Turbo учитывает граф зависимостей и кеширует
сборки и типизацию. Кеш бинарников сейчас только локальный; общую межплатформенную
систему кеширования необходимо проектировать вместе с выпуском.

Добавление зависимости конкретному потребителю:

```bash
bun add --cwd packages/contracts <package>
bun add --dev --cwd apps/cli <package>
```

## Тесты

```bash
bun run test
bun run test:integration
bun run test:process
bun run test:e2e
```

`test` запускает только модульный набор. Правила разделения, имена файлов и запуск
выбранного владельца описаны в [tests/README.md](tests/README.md).
В каркасе тестов поведения пока нет: пустые наборы явно допускаются, фиктивные тесты
не добавлены. Это подготовка запуска, а не свидетельство покрытия продукта.
