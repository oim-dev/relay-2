# Relay

Relay — рабочая память проекта для людей и AI-агентов. Он помогает сохранять
описание продукта, решения, документы и задачи вместе с контекстом работы.
К этим сведениям можно вернуться в следующей сессии и продолжить работу,
опираясь на сохранённые договорённости.

## Для чего нужен Relay

Relay полезен, когда знания о проекте распределены между обсуждениями, документами
и задачами. Он связывает требования с работой над ними: позволяет описать фичу,
сохранить сопутствующий документ, поставить задачи с критериями приёмки и включить
их в план.

История работы сохраняет намерения и результаты участников. Поиск и обзор помогают
восстановить контекст, а вычисляемый прогресс учитывает зависимости и обязательства.
Несколько независимых проектов можно объединить в локальный workspace для удобного
выбора из командной строки или браузера.

Relay хранит сведения о работе; изменение кода, выполнение проверок и публикацию
программ выполняют человек, агент или другие инструменты.

## Как пользоваться

С проектом можно работать через локальную команду `relay` и браузерный Web-интерфейс.
Данные каждого проекта хранятся в отдельной SQLite-базе на вашем компьютере.
CLI подходит для интерактивного использования и скриптов: результаты можно получать
как читаемый текст или JSON; локальные команды работают без сервера и сети.

Для Web команда `relay server run` запускает локальный Server со встроенным интерфейсом
и REST API. В браузере доступны знания, документы, доски задач, планы, релизы и история.
CLI и Web работают с теми же данными; внешние изменения обновляют открытые страницы,
сохраняя несохранённый ввод редактора. Начните с [запуска Server и Web](docs/CLI.md#сервер-и-web).

Новая версия находится в разработке. Для обмена независимых локальных реплик развивается
Git Sync с командами `relay git-sync`: подключение общей ветки, ручной и фоновый обмен,
просмотр конфликтов и восстановление из Git. Он работает отдельным компонентом,
сохраняя локальную работу без сети. В Git передаются переносимые записи проекта;
рабочая SQLite остаётся на компьютере. Начать знакомство можно с
[руководства синхронизации](docs/CLI.md#git-синхронизация).
Для постоянного обмена supervisor запускается явно через `relay git-sync service enable`
или удерживается foreground-командой `relay git-sync supervise`; ручной `now` доступен без него.
Удалённый режим CLI, MCP, PostgreSQL, установщик и перенос данных из первой версии
остаются следующими этапами.

## Быстрый старт

Для сборки из исходников нужны Bun **1.4.3**, закреплённый в `.bun-version` и `packageManager`,
и **Node.js 24+** для Vite. Bun устанавливает зависимости, собирает бинарники и запускает
тесты; Vite выполняется под Node.js.
Установка: [Bun](https://bun.com/docs/installation), [Node.js](https://nodejs.org/en/download).
Следующие команды выполняются из корня репозитория:

```bash
bun --version
node --version
bun install --frozen-lockfile
bun run build:cli
apps/cli/dist/relay --help
```

Сборка подготавливает согласованные бинарники `apps/cli/dist/relay`,
`apps/server/dist/relay-server` со встроенным Web и `apps/git-sync/dist/relay-git-sync`
(на Windows — с расширением `.exe`). Для запуска готовых бинарников Bun и Node.js не нужны.
Для самого Git-обмена нужен установленный Git и доступ к выбранному remote.
Справка работает без настроенного проекта.
Следующий шаг — [создать проект и сохранить первый документ](apps/cli/README.md#первый-проект).

## Разработка и ручное тестирование

При совместной разработке с AI-агентом пользователь в основном знакомится с результатом
и тестирует Relay в playground. В нашей рабочей области он находится в
`/home/gromov/projects/relay/playground` — рядом с `relay-2`, по пути `../playground`.
Агент выбирает удобную среду разработки и своих проверок, а результаты передаёт
для ручной проверки в playground через обновлённую команду `relay`.

Playground объединяет два самостоятельных проекта: `projects/commerce` и
`projects/observability`. Из корня playground запускается режим workspace, из корня
каждого проекта с `relay.config.json` — локальный режим. Настройка `.envrc`, подключение
бинарника из `relay-2` и команды развёртывания
описаны в [README playground](https://github.com/oim-dev/relay-playground).
Запуск workspace в браузере и проверка совместной работы CLI/Web приведены в
[сценарии playground](docs/CLI.md#проверить-cli-и-web-в-playground).
