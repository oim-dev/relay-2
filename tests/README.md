# Организация тестов Relay

Тестовый runner — Bun test. В каркасе тестов поведения ещё нет. Флаг
`--pass-with-no-tests` позволяет подготовить команды до появления реализации;
сообщение об отсутствии тестов не является доказательством качества или покрытия.
При появлении первого набора владельца убирайте этот флаг из соответствующего script,
чтобы случайная потеря набора становилась ошибкой.

## Наборы

| Набор              | Размещение                                               | Команда из корня                                |
| ------------------ | -------------------------------------------------------- | ----------------------------------------------- |
| Модульный          | `src/**/*.unit.test.ts` у владельца                      | `bun run test:unit` или `bun run test`          |
| Интеграционный     | `tests/integration/**/*.integration.test.ts` у владельца | `bun run test:integration`                      |
| Процессный         | `apps/{cli,sync}/tests/process/**/*.process.test.ts`     | `bun run test:process`                          |
| Сквозной           | `tests/e2e/**/*.e2e.test.ts` в корне                     | `bun run test:e2e`                              |
| Производительность | `benchmarks/`                                            | Команда появится вместе с измерительным стендом |

Модульные и интеграционные наборы работают с исходными модулями, без предварительной
сборки бинарников. Процессные зависят от Turbo-задачи `build` своего приложения.
Сквозной вход подготавливает все приложения. Успешные сборки переиспользуются из кеша.
Процессные, интеграционные и сквозные результаты сейчас не кешируются.

Адресный запуск:

```bash
bun --bun turbo run test:unit --filter=@relay/core
bun --bun turbo run test:integration --filter=@relay/storage
bun --bun turbo run test:process --filter=@relay/cli
```

## Принципы

- Тест проверяет наблюдаемое поведение, инвариант или отказ, а не копирует реализацию.
- Проверки заглушек и искусственное достижение процента покрытия не добавляются.
- Чистые правила проверяются быстро внутри процесса. Хранилище и Git проверяются
  на настоящих изолированных ресурсах; процессные сценарии используют бинарники.
- У каждого теста собственные данные, каталоги, порты и процессы с обязательной очисткой.
  Пользовательская база, origin и Playground не используются как fixtures.
- Общие helpers имеют конкретного владельца. Универсальный сценарный фреймворк
  и скрытые зависимости между fixtures не вводятся заранее.
- Ожидаем наблюдаемое состояние с deadline. Автоматические повторы провалившихся тестов
  и произвольные долгие задержки не скрывают нестабильность.
- Межпакетную параллельность задаёт Turbo. Конкурентность внутри набора включаем после
  подтверждения изоляции ресурсов; общего `--concurrent` для всех тестов нет.
- Браузерный инструмент подключается вместе с первым реальным Web-сценарием.
  Сквозной HTTP-тест сам по себе не доказывает работу интерфейса человека.
- Миграции, конкуренция, конфликты, потеря ответа и аварийное завершение входят
  в сценарии соответствующего механизма по мере его реализации.

Покрытие модульного набора можно измерить адресно:

```bash
bun run --filter @relay/core test:unit --coverage
```

Порог покрытия устанавливается при появлении содержательной реализации. Время запуска,
нагрузка на диск, p95/p99 и память измеряются отдельно, на зафиксированном окружении.
