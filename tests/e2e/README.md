# Сквозные сценарии

Набор `*.e2e.test.ts` проверяет законченные пользовательские маршруты через
собранный бинарник CLI. Каждый шаг запускает отдельный процесс:

- инициализация проекта, сохранение полного Markdown и изменение по ревизии;
- выбор независимых проектов через локальный workspace;
- выполнение задачи с критерием, завершение плана и фиксация релиза;
- сохранение неизменяемого намерения, результата и завершение агентского участия;
- проверка и применение связанной декомпозиции пакетом, групповое чтение и
  восстановление исходной квитанции после нового запуска CLI;
- подключение к Git, восстановление второго участника и сходимость точечных записей
  и пакетов: точный Markdown, коллизии ключей, независимые поля и ссылки по ID;
- показ трёх сторон реального конфликта тела и сохранение явного решения при обмене;
- включение автоматического обмена, чтение состояния и остановка worker из разных процессов.

Проверки отдельных команд находятся в `apps/cli`, правил — в `packages/core`, хранения —
в `packages/storage`. Сквозной маршрут подтверждает соединение возможностей продукта;
детальные варианты одного правила остаются у владельца.

Запуск — `bun run test:e2e` из корня; Turbo предварительно собирает `relay` и
`relay-git-sync`. Для адресного запуска Git-маршрутов:

```bash
bun run build:cli
bun test --no-orphans --cwd tests/e2e git-sync
```

Для Git-сценариев нужен `git` в PATH. Участники используют разные HOME и RELAY_HOME,
общий локальный bare remote и изначально пустые рабочие каталоги. Фоновые процессы
останавливаются при завершении маршрута, включая падение утверждения. Worker-маршрут
сначала запускает собственный `relay git-sync supervise` и ждёт готовности по протоколу.
Перед удалением HOME fixture останавливает worker, supervisor и дожидается выхода CLI.
Ручные connect/restore/now не требуют supervisor. Проверки не
устанавливают нативные службы ОС; подробный жизненный цикл и входящая доставка без
локальных записей проверяются процессным набором `apps/git-sync`.
Runner использует `--no-orphans` как дополнительную очистку потомков при аварийном завершении.

Нагрузочные измерения принадлежат
[benchmarks](../../benchmarks/README.md) и в этот набор не включаются.

Общие правила: [организация тестов](../README.md).
