# Сквозные сценарии продукта

Набор `*.e2e.test.ts` проверяет четыре межприложенческих пользовательских маршрута через
собранные бинарники CLI и Server. Git Sync встроен в CLI; CLI-шаги запускают отдельные процессы,
HTTP-шаги используют REST SDK и принадлежащий fixture сервер:

- подключение к Git, восстановление второго участника и сходимость точечных записей
  и пакетов: точный Markdown, коллизии ключей, независимые поля и ссылки по ID;
- показ трёх сторон реального конфликта тела и сохранение явного решения при обмене;
- сохранение manual/auto и явная доставка через now без постоянного процесса;
- поставка Web внутри Server, запись через HTTP и чтение через CLI, отказ устаревшей версии,
  сохранение первоначальной квитанции и доставка актуального документа второй Git-реплике.

Локальные маршруты без Server и Git Sync находятся в [CLI E2E](../../apps/cli/tests/e2e/README.md)
и этим набором не запускаются. Проверки отдельных команд находятся в `apps/cli`, правил —
в `packages/core`, хранения — в `packages/storage`. Сквозной маршрут подтверждает соединение
возможностей продукта; детальные варианты одного правила остаются у владельца.

Subprocess-harness CLI переиспользуется прямым импортом из `apps/cli/tests/e2e/helpers`;
корневые helpers владеют только Git-окружением, remote и жизненным циклом Server.

Общий запуск — `bun run test:e2e` из корня вместе с CLI E2E; Turbo предварительно собирает `relay`,
и `relay-server` со встроенным Web. Для сборки нужны Bun и Node.js 24+
по [быстрому старту](../../README.md#быстрый-старт). Адресные запуски:

```bash
bun run build:cli
bun run test:e2e:product
bun test --no-orphans --cwd tests/e2e git-sync
bun test --no-orphans --cwd tests/e2e server-web-workflow.e2e.test.ts
```

Для Git-сценариев нужен `git` в PATH. Участники используют разные HOME и RELAY_HOME,
общий локальный bare remote и изначально пустые рабочие каталоги. Процессы запросов
завершаются до удаления fixture, включая падение утверждения. Обмен выполняется через
linked worktree каждой реплики. Проверки не устанавливают нативные службы ОС;
подробный lifetime и доставка при пустом outbox проверяются в `packages/git-sync/tests/process`.
Runner использует `--no-orphans` как дополнительную очистку потомков при аварийном завершении.

Server-маршрут копирует `relay-server` в отдельный каталог и запускает его с собственным
home и свободным портом. Fixture ждёт опубликованного loopback URL и останавливает
процесс при cleanup; дальнейшие запросы проверяют доступность настоящего API.
Он запрашивает HTML по вложенному Web-маршруту и production JavaScript, но не запускает
браузер. UI-формы, темы, мобильная навигация и работа с черновиками относятся к
[браузерной приёмке](../README.md#браузерные-сценарии-web).

Нагрузочные измерения принадлежат
[benchmarks](../../benchmarks/README.md) и в этот набор не включаются.

Общие правила: [организация тестов](../README.md).
