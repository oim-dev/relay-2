# Изменения Project Runtime

Перед работой прочитай [паспорт пакета](README.md). Следуй
[корневым инструкциям](../../AGENTS.md), [стайлгайду TypeScript](../../docs/development/TYPESCRIPT-STYLEGUIDE.md),
[правилам тестов](../../docs/development/TESTING.md) и [документации](../../docs/development/DOCUMENTATION.md).

- Здесь принадлежат пути, локальная конфигурация, инициализация и реестр workspace.
  Предметные изменения выполняет Core, механизм SQLite и mutex — Storage;
  Git-транспорт и пользовательский вывод не входят в Runtime.
- Контекст передаётся через `RuntimeOptions`. `cwd` обязателен; `config` и `home`
  разрешаются относительно него. Окружение читает CLI: не добавляй чтение RELAY_HOME
  или изменение глобального рабочего каталога внутри сценариев.
- Относительные пути из JSON разрешаются от физического каталога конфига, включая
  symlink. Явный конфиг сохраняет приоритет; `project` выбирает регистрацию workspace,
  а не игнорируется при явно указанном проектном конфиге.
- Поиск вверх не пропускает повреждённый ближайший конфиг или битую ссылку.
  В одном каталоге проект имеет приоритет; выбор по имени ищет workspace.
- При выборе проверяй наличие, совместимость базы и совпадение projectId с конфигом.
  Потерянная база не создаётся заново; проверочное соединение закрывается и не
  обещает удержание снимка для последующего сценария вызывающего.
- Инициализация проверяет вход до записи, создаёт собственный каталог нового ID
  и публикует конфиг эксклюзивно после готовности БД. Проигрыш гонки не заменяет
  чужой конфиг; уборка удаляет только каталог своей попытки. Неявный init сохраняет
  защиту от вложенного проекта внутри существующего проекта.
- Изменение workspace удерживает один mutex на физический путь файла на всём
  read-modify-write. Публикуй целый JSON атомарной заменой; разные symlink должны
  конкурировать за тот же замок. Не заменяй mutex эвристикой возраста lock-файла.
- Повтор регистрации того же имени и пути — no-op; другой путь с тем же именем —
  конфликт. Удаление регистрации не удаляет проект; список и удаление должны
  оставаться доступны при недоступной базе зарегистрированного проекта.

## Размещение кода и импорты

- `src/project/` содержит создание и выбор проекта, проверку имени/slug и контракт
  расположения базы; `src/workspace/` — операции локального реестра и его контракты.
- `src/configuration/` отвечает за формат и чтение конфигов, поиск путей, файловые
  ошибки и атомарную публикацию; здесь находится общий контекст `RuntimeOptions`.
- Типы, сообщения и константы располагаются рядом с владельцем ответственности.
  Внутренние модули импортируют реализацию и `*.types.ts` напрямую, без промежуточных
  `index.ts` и общих каталогов `types`, `utils` или `helpers` в исходниках.
- `src/index.ts` — единственный публичный entrypoint `@relay/project-runtime`.
  Интеграционные тесты и workers используют этот импорт, сохраняя свои пути
  в `tests/integration/`.

## Проверки

Адресный набор из корня: `bun run --filter @relay/project-runtime test:integration`.
В `tests/integration/*.integration.test.ts` выбирай `config` для путей и схемы,
`project-naming` для имени/slug, `runtime` для выбора и инициализации, `workspace`
для реестра, `concurrency` для гонок публикации и регистрации. Используй изолированные
`cwd` и `home`; при изменении mutex проверь также `local-lock` в Storage, а при
изменении выбора проекта — интеграцию `project-context` CLI.
