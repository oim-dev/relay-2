# Изменения Storage

Перед работой прочитай [паспорт пакета](README.md). Общие требования:
[корневые инструкции](../../AGENTS.md), [TypeScript](../../docs/development/TYPESCRIPT-STYLEGUIDE.md),
[тесты](../../docs/development/TESTING.md), [документация](../../docs/development/DOCUMENTATION.md).

- Storage владеет SQL, технической схемой, соединением и механизмами конкурентности.
  Предметную форму вложенного `data` и допустимость сценария проверяет Core;
  выбор пути и жизненный цикл конфигурации принадлежат Runtime.
- `transaction` использует `BEGIN IMMEDIATE`, `snapshot` — `BEGIN DEFERRED`;
  вложенные вызовы используют savepoint. Оба callback синхронны: async не запускается,
  возвращённый Promise/thenable приводит к отказу и откату своей области.
- Откат возвращает также алиасы, счётчики и поколение. Перехваченный отказ вложенной
  транзакции не оставляет её изменений во внешней; закрытие активной транзакции запрещено.
- CAS проверяет постоянный ID и исходную ревизию. Обновление увеличивает ревизию
  содержания ровно на один; `rename` проверяет её и перед no-op. ID, вид и поля создания
  неизменяемы, ID/ключи/алиасы делят одно пространство адресов.
- Журнал комментариев append-only и хранится отдельно от содержания задачи.
  Добавление меняет поколение, но не ревизию содержания; CAS со старой проекцией
  комментариев не должен удалить новые записи журнала.
- `listPage` читает total и SQL-окно в одном снимке, декодируя только окно.
  Сохраняй устойчивый порядок по ID при равенстве ключей сортировки. Проекции
  идентичности и графа не должны загружать полные тексты и журналы задач.
- Файловая БД работает в WAL с внешними ключами. `open` отвергает отсутствующую,
  чужую и несовместимую базу; `create` не заменяет занятый файл и убирает только
  собственные файлы после отказа создания.
- `withLocalFileLock` удерживает межпроцессный mutex соединением SQLite.
  Lock-файл не удаляется после освобождения; исключение не откатывает JSON вызывающего.
  Атомарная публикация JSON остаётся ответственностью Runtime.

## Структура и зависимости

- `src/database/` — фасад проекта, жизненный цикл файла и границы транзакций;
  `src/entities/` — SQL-чтение и запись сущностей, ключей и журнала комментариев.
- `src/sqlite/` — техническая схема, ошибки драйвера, настройки и общий синхронный
  контракт callback; `src/local-lock/` — mutex локального JSON-файла.
- `database` связывает `entities` и `sqlite`; `local-lock` зависит только от `sqlite`.
  Нижние механизмы не импортируют фасад базы или блокировку. Типы, диагностики и
  константы располагаются рядом с механизмом-владельцем.
- `src/index.ts` — публичная точка входа `@relay/storage`. Внутри пакета, включая
  тесты, импортируй файлы-владельцы напрямую; промежуточные barrel-модули не создавай.

## Проверки

Из корня адресный набор: `bun run --filter @relay/storage test:integration`.
Для транзакций/CAS выбирай `transactions` и `concurrent-writers`, для журнала —
`task-comments`, для окон — `pages`, для жизненного цикла БД — `database`, для mutex —
`local-lock` в `tests/integration/*.integration.test.ts`. WAL, блокировки, rollback
и повторное открытие проверяй на реальной файловой SQLite; изменение mutex требует
также сценариев конкурентного workspace в Runtime. Запуск одного файла описан
в [руководстве тестов](../../tests/README.md#запуск-и-сборка).
