# ТЗ: групповое чтение и атомарные пакеты Relay CLI

## Назначение

Агент и человек получают выбранный рабочий набор одним вызовом и применяют
подготовленную последовательность предметных изменений без скрипта, который
сохраняет промежуточные адреса. Область операции — один выбранный локальный проект.

Новые точки входа — `get` и `batch`. Группа `inspect` удаляется, включая `resolve`:
совместимых алиасов не требуется. Верхнеуровневые `create` и `update` не добавляются.
Одиночные предметные команды используют те же правила Core, что и пакет.

## Групповое чтение

```bash
relay get DOC-1 TASK-1 PLAN-1
relay get DOC-1 TASK-1 PLAN-1 --summary
relay get DOC-1 TASK-1 PLAN-1 --format json
```

- Принимается от 1 до 200 адресов: ID, ключи, алиасы и типизированные ссылки.
- Порядок и повторы аргументов сохраняются; каждый результат содержит исходный адрес.
- По умолчанию возвращаются полные предметные записи, включая полные тексты.
- `--summary` возвращает только идентичность, ревизию, название и применимые
  показатели сохранённого состояния, как краткая карточка списка. Тела документов,
  описания, критерии, комментарии и содержимое связанных записей не возвращаются.
  Хранилище выбирает краткую проекцию без передачи полных тел и журналов в Core.
  Выбранные поля проверяются по правилам их предметных владельцев; допустимые
  значения одинаковы для полного и краткого чтения. Невыбранное содержание
  краткое чтение не декодирует.
- Чтение выполняется в одном согласованном снимке. Общие индексы строятся один раз;
  загрузка всего проекта для адресного набора запрещена.
- Полное чтение соответствует предметному `get`, в частности документ с удалённым
  разделом показывается вне раздела. Повреждённые данные не исправляются молча.
- Для известной ошибки отдельного адреса возвращается ошибочный элемент рядом с
  успешными. Неожиданная инфраструктурная ошибка прерывает вызов. При ошибочных
  элементах код завершения ненулевой; код первой ошибки определяется порядком входа.
- JSON имеет одинаковую форму списка для одного и нескольких адресов. Полный и краткий
  варианты явно различаются полем представления; ошибки имеют стабильный код и детали.
  Частичный результат публикуется как единый JSON с `ok: false` и всеми элементами.

### Границы текстового вывода

Каждый результат, включая ошибочный, оформляется отдельным блоком с начальным
заголовком, номером и исходным адресом. Разделители ставятся только перед записями;
между блоками остаётся пустая строка. Для найденной записи указываются её
текущие ключ, вид и ID. Заголовок используется и для одной записи. В кратком
режиме блок компактный. Управляющие последовательности очищаются существующим
механизмом CLI, а Markdown и значимые переводы строк полного содержания сохраняются.

## Пакет предметных изменений

```bash
relay batch --actor agent --operation-key publish-spec-v2 --input @changes.json
relay batch --actor agent --input @changes.json --check
relay batch result publish-spec-v2
```

Единственный параметр источника — `--input`: значение с начальным `@` читает UTF-8
файл по указанному пути, `-` читает stdin, остальные значения разбираются как JSON.
Например, `--input '{"version":1,"operations":[...]}'` передаёт JSON непосредственно,
а `--input @changes.json` читает файл. Путь считается относительно рабочего каталога
вызова. Отдельного `--input-file` у batch нет. Вход ограничен 8 MiB и полностью читается
до транзакции. Версия формата обязательна. Допускается от 1 до 200 операций.

```json
{
  "version": 1,
  "operations": [
    {
      "op": "document.create",
      "as": "new-spec",
      "input": {
        "name": "Правила бронирования, редакция 2",
        "body": "Актуальные правила бронирования переговорных.",
        "documentStatus": "active"
      }
    },
    {
      "op": "document.update",
      "ref": "DOC-1",
      "ifRevision": 3,
      "input": { "documentStatus": "archived" }
    }
  ]
}
```

### Каталог операций

Пакет использует имена предметных действий с точками: `document.create`,
`document.update`, `feature.create`, `scenario.create`, `implementation.create`,
`task.create`, `task.move`, `task.criterion.add`, `plan.stage.create` и т. п.
Общая справка `batch -h` содержит формат пакета, основные параметры, гарантии,
короткий пример и навигацию. Подробный каталог всех операций в ней не печатается.

```bash
relay batch help
relay batch help plan
relay batch help plan stage
relay batch help plan stage create
relay batch help product create
```

`batch help` перечисляет предметные разделы, промежуточные группы — только действия
и подгруппы выбранного уровня. Конкретная операция раскрывает свой JSON-контракт:
`ref`, владельца ревизии, поля `input`, предметные условия и копируемый пример пакета.
Вызов с `-h` равнозначен обычному вызову такого узла справки. Справка работает без
проекта, БД, автора и stdin; её чтение не выполняет предметные действия.

Каждое поле `input` описывается отдельно: тип значения, назначение, обязательность,
поведение при пропуске и допустимость `null`, явная пометка Markdown, перечисления
и формат ссылок. Описания общих полей переиспользуются из справки предметных команд;
пакетные отличия и структурированные JSON-поля объясняются явно. Краткие названия
операций отражают предметное действие; CAS описывается отдельно у своего владельца.
Подробности выбранной операции формируются лениво, без обхода полей всего каталога
при запуске обычных команд либо чтении общей навигации.
Поля `input` соответствуют предметному JSON-вводу; дополнительные адресные аргументы
вложенных действий имеют явный контракт: `ref` адресует владельца, а ID этапа/критерия
и связанные цели передаются в `input`. Примеры и таблица находятся в
[руководстве CLI](docs/CLI.md#вложенные-действия-пакета), подробности конкретного
действия — в соответствующем `relay batch help …`. Неизвестные операции и поля отклоняются.
Операции над настройками, workspace и жизненным циклом файла проекта не входят
в транзакционный пакет. Глобального произвольного изменения JSON сущности нет.

### Локальные результаты и ревизии

- `as` — уникальное локальное имя результата, действующее только внутри пакета.
- `{"$ref":"booking"}` в адресном поле использует ID основного результата предыдущей
  операции `as: "booking"`. Для этапа и критерия основным результатом является вложенный
  объект. Ссылки вперёд, неизвестные имена и неверные типы целей отклоняются.
- Имена не становятся постоянными ключами или алиасами. Обычная строка адресует
  существующую запись через стандартный механизм Core.
- `{"$revision":"previous-change"}` в `ifRevision` использует ревизию владельца,
  возвращённую предыдущим изменением. Для этапа это план, для критерия — задача.
  Связь результата с владельцем проверяется; чужую ревизию использовать нельзя.
- Первая правка существующего владельца требует числовую прочитанную ревизию.
  Исполнитель не подставляет свежую ревизию автоматически. Комментарии сохраняют
  собственный контракт независимого дописывания без CAS содержания задачи.
- Подстановка выполняется только в объявленных адресных полях и в `ifRevision`.
  Пользовательские строки и Markdown не интерполируются.

### Атомарность и предварительная проверка

Операции выполняются в объявленном порядке через предметные сервисы Core в одной
SQLite-транзакции. Ошибка исполнения до commit откатывает изменения, алиасы, счётчики, поколение и
квитанцию. Ошибка содержит индекс операции, её имя и адрес проблемного поля.
Результат не объявляет откатившиеся элементы успешно сохранёнными.

`--check` использует тот же предметный исполнитель с принудительным откатом,
не сохраняет квитанцию и не расходует ключ операции. Подготовительные ID и ключи
не являются резервированием. При применении все проверки выполняются заново.

### Результат и повторное выполнение

- По умолчанию выводится компактная квитанция: общий исход и результаты операций,
  локальные имена, ключи, виды, постоянные ID и ревизии владельцев.
- `--return full` добавляет полное итоговое содержание затронутых сущностей из
  транзакции пакета. Повторное чтение для получения созданного содержания не требуется.
- `--operation-key` задаётся вызывающим; область уникальности — выбранный проект.
  Для применения пакета ключ обязателен, для `--check` не требуется.
- Успешная квитанция и нормализованный запрос с автором сохраняются атомарно с данными.
  Повтор того же запроса возвращает первоначальный результат до повторной проверки
  адресов и ревизий. Другой запрос или автор под тем же ключом вызывает конфликт.
- Нормализация работает с распарсенным JSON и рекурсивно упорядочивает свойства
  объектов. Пробелы оформления JSON и порядок свойств не значимы. Порядок массивов
  и операций, значения строк, исходные адреса, локальные имена и наличие полей
  значимы: явно заданное значение по умолчанию отличается от пропущенного поля.
  Замена ключа сущности на её ID также является другим запросом. Нормализация не
  обращается к БД и не разрешает ссылки; автор сравнивается дословно. Источник ввода,
  формат вывода, `--return`, `--check` и сам ключ операции не входят в содержимое запроса.
- `batch result <ключ>` читает первоначальную квитанцию после перезапуска. Это результат
  исходной операции, а не текущие версии сущностей. Ключи автоматически не истекают.
- Форматирование text/JSON и выбор компактного/полного представления не меняют
  предметную идентичность операции. Ошибка вывода после commit не отменяет запись;
  повтор с тем же ключом безопасно восстанавливает результат.

## Границы реализации

- Contracts: переносимые точные контракты результатов, ссылок и ошибок.
- Core: групповое чтение, разрешение локальных ссылок и оркестрация предметных операций.
- Storage: ограниченные адресные выборки, транзакции и журнал квитанций с технической
  миграцией существующей локальной базы без потери её данных.
- CLI: разбор аргументов, ограниченный ввод, справка, потоки и представление.

Каждая команда открывает выбранную БД один раз. Предметные действия не выполняются
запуском вложенных процессов CLI. Пакет не обещает один SQL-запрос: повторные полные
чтения графов и стоимость больших составов проверяются отдельно по коду и тестам.

## Приёмка

1. Смешанное чтение документов, задач и планов, порядок, повторы и адресные ошибки.
2. Полный Markdown и ясные границы записей в text; стабильная форма JSON, включая
   один элемент и частичный отказ. Краткий вывод не содержит тел и вложенных составов.
3. `inspect` отсутствует в справке, автодополнении и дереве команд; руководства и
   проверяемые сценарии используют `get`.
4. Создание связанной фичи, сценария, реализаций и задач с локальными ссылками;
   смешанный пакет создания документа и изменения статусов существующих документов.
5. Последовательные изменения плана и критериев используют ревизии правильного владельца.
6. Неверная ссылка, тип цели, доска, обязательство или ревизия откатывают весь пакет.
7. `--check` сохраняет исходное состояние и не препятствует последующему применению.
8. Повтор после повторного открытия БД возвращает те же ID и квитанцию без новых
   сущностей; изменённый запрос под тем же ключом конфликтует.
9. Миграция сохраняет сущности, алиасы, ревизии, комментарии и поколение старой базы.
10. Тесты выполняются на изолированных fixtures; сборка CLI обновляет пользовательский
    бинарник. Нагрузочные измерения в эту приёмку не входят.
